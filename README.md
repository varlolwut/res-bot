# res-bot

<p align="center">
  <img src="assets/res-bot-icon.png" width="128" height="128" alt="Логотип res-bot">
</p>

`res-bot` — фоновый Windows-помощник для диалога воскрешения в Lineage II. Он
анализирует только изображение активного окна игры и управляет обычным курсором
мыши. Приложение не читает память Lineage II, не внедряет код в процесс, не
устанавливает драйверы и не использует игровые сетевые протоколы.

## Что делает MVP

Раз в 10 секунд приложение:

1. Проверяет, что активное окно похоже на Lineage II.
2. Снимает клиентскую область окна через Windows GDI.
3. Находит диалог воскрешения по паре зелёной и красной кнопок.
4. Распознаёт процент восстановления опыта встроенным Windows OCR.
5. Находит панель персонажа по расположенным рядом цветным полосам MP/VP и
   распознаёт ник в верхней части панели.
6. Выбирает действие по таблице:

| Процент | Ник заканчивается на `_NN` | Действие |
|---:|:---:|:---|
| `0%` | нет | красная кнопка «Отменить» |
| `100%` | нет | зелёная кнопка «ОК» |
| `0%` или `100%` | да | зелёная кнопка «ОК» |

`NN` — ровно две любые цифры от `00` до `99`. Основная часть ника может быть
любой и не задаётся в конфигурации.

Перед нажатием приложение подтверждает одинаковые процент, суффикс ника и решение
на нескольких последовательных кадрах, а после ожидания свободной мыши ещё раз
проверяет активное окно и положение диалога. Курсор движется по плавной кривой со
случайной длительностью, а точка нажатия выбирается внутри безопасной области
кнопки.

## Дополнительные функции

- количество подтверждающих кадров и интервал между ними настраиваются;
- учитывается только ручное движение курсора: нажатия кнопок мыши и макросных
  клавиш не блокируют работу;
- если пользователь начинает двигать мышь во время автоматического движения,
  клик отменяется;
- после успешного клика курсор может переместиться в случайную близкую точку;
  функцию можно отключить;
- настройки открываются из трея и применяются без перезапуска;
- самопроверка из трея проверяет OCR, конфигурацию, активное окно, захват кадра,
  диалог и панель персонажа, но никогда не выполняет клик.

## Быстрый запуск

Требования:

- Windows 10 или Windows 11 x64;
- установленный русский языковой компонент OCR Windows;
- Lineage II запущена с тем же или более низким уровнем прав, что и `res-bot`.

Запуск:

1. Скачайте `res-bot.exe`.
2. Запустите файл.
3. Убедитесь, что в области уведомлений появился зелёно-золотой значок `res-bot`.
4. Оставьте окно Lineage II активным.

Порядок запуска не важен: `res-bot` можно открыть до или после игры. Если игра
ещё не запущена или её окно неактивно, приложение остаётся в ожидании. После
переключения на Lineage II проверка произойдёт в течение ближайшего интервала,
по умолчанию — не позднее чем через 10 секунд. Если игра запущена от
администратора, `res-bot` также следует запустить от администратора.

Приложение проверяет доступность русского OCR до появления значка в трее. Если
значок появился без сообщения об ошибке, компонент доступен. Для ручной проверки
откройте Windows PowerShell от имени администратора:

```powershell
Get-WindowsCapability -Online |
  Where-Object { $_.Name -like 'Language.OCR*ru-RU*' }
```

Установленному компоненту соответствует `State : Installed`. Если показано
`NotPresent`, установите его:

```powershell
Get-WindowsCapability -Online |
  Where-Object { $_.Name -like 'Language.OCR*ru-RU*' } |
  Add-WindowsCapability -Online
```

Окно консоли в release-сборке не открывается. В меню значка `res-bot` доступны
«Настройки», «Диагностика», «Самопроверка» и «Выход». Горячая клавиша
`Ctrl+Shift+F12` остаётся резервным способом завершения.

Без конфигурационного файла используются значения, подходящие для показанных
примеров: интервал 10 секунд и поиск слова `lineage` в заголовке активного окна.

## Необязательная конфигурация

Чтобы изменить параметры, положите рядом с `res-bot.exe` файл `res-bot.toml`.
Все поля обязательны:

```toml
window_title_fragments = ["lineage"]
poll_interval_seconds = 10
click_min_duration_ms = 280
click_max_duration_ms = 650
pre_click_min_delay_ms = 180
pre_click_max_delay_ms = 480
confirmation_frame_count = 2
confirmation_interval_ms = 150
mouse_idle_required_ms = 600
mouse_idle_timeout_ms = 3000
relocate_cursor_after_click = true
```

Пример также находится в
[`res-bot.example.toml`](res-bot.example.toml).

## Настройки через трей

Окно «Настройки» позволяет менять те же параметры без ручного редактирования
TOML:

- «Применить» обновляет конфигурацию работающего процесса и не создаёт файлов;
- «Сохранить» обновляет процесс и записывает единственный `res-bot.toml` рядом с
  `.exe`, чтобы использовать значения после перезапуска;
- «Отмена» закрывает окно без изменений.

Реестр Windows для хранения настроек не используется. Если рядом с `.exe` нельзя
создавать файлы, «Сохранить» покажет конкретную ошибку; «Применить» продолжит
работать без записи.

## Как работает распознавание

Полный кадр не передаётся OCR целиком. Сначала приложение ищет цветовые и
геометрические признаки интерфейса:

1. Пара похожих кнопок «зелёная слева, красная справа» определяет кандидат
   диалога.
2. Область над кнопками обрезается, переводится в контрастный вид, увеличивается
   в три раза и передаётся русскому Windows OCR.
3. В OCR-тексте ищется отдельное `0%` либо `100%`.
4. Панель персонажа независимо ищется по расположенным рядом синим и зелёным
   полосам MP/VP в любой части кадра.
5. Область панели увеличивается в три раза; OCR-текст проверяется на суффикс
   `_NN`.
6. Процент, наличие `_NN` и итоговое действие должны совпасть на 2–5
   последовательных кадрах.
7. После ожидания неподвижного курсора повторно проверяются активное окно, HWND
   и положение диалога.

Если процент, панель или похожий на ник текст не распознаны однозначно,
приложение ничего не нажимает и продолжает работу.

## Диагностика по запросу

Диагностика по умолчанию выключена и не создаёт файлов.

1. Нажмите левой или правой кнопкой мыши на значок `res-bot` в трее.
2. Выберите «Диагностика».
3. Вернитесь в Lineage II и воспроизведите сценарий.
4. Просмотрите журнал в диагностическом окне. Оно остаётся поверх других окон,
   но не должно активироваться вместо игры.
5. Используйте «Копировать», чтобы поместить весь журнал в буфер обмена, либо
   «Очистить», чтобы начать новую диагностическую последовательность.
6. Закройте диагностическое окно, чтобы остановить сбор.

Во время диагностической сессии в оперативной памяти хранится не более 500
строк. Записываются результаты проверки окна, размеры кадра, координаты
найденного диалога и панелей, OCR-текст, решение, повторная проверка и итоговый
клик. После закрытия окна новые строки не формируются; на диск журнал
автоматически не сохраняется.

## Самопроверка

1. Откройте меню значка в трее и выберите «Самопроверка».
2. Подтвердите запуск и в течение трёх секунд вернитесь в Lineage II.
3. Дождитесь окна с результатами.

Самопроверка отмечает каждый этап как `[OK]`, предупреждение `[!]` или ошибку
`[X]`. Отсутствие открытого диалога воскрешения является предупреждением, а не
ошибкой захвата. Во время самопроверки автоматические клики приостановлены.

## Если бот не нажимает кнопку

Откройте диагностику, вернитесь в игру и дождитесь следующего цикла. Наиболее
частые причины:

- Lineage II не является активным окном;
- заголовок окна не содержит настроенный фрагмент `lineage`;
- не найдена подходящая пара зелёной и красной кнопок;
- русский OCR не обнаружил `0%` или `100%`;
- не найдена видимая панель с полосами MP/VP;
- OCR не распознал похожий на ник текст;
- окно или диалог изменились во время задержки перед кликом.

## Сборка

```powershell
cargo test
cargo build --release
```

Готовый файл появится в `target\release\res-bot.exe`. Все необходимые библиотеки
Rust компонуются в исполняемый файл; отдельный Tesseract и файлы моделей не
нужны. OCR предоставляется самой Windows.

Workflow GitHub Actions собирает и сохраняет `res-bot.exe` как artifact при каждом push
и ручном запуске. При публикации тега вида `v*` тот же workflow создаёт GitHub Release и
прикрепляет к нему готовый `res-bot.exe`.

## Ограничения MVP

- Обрабатывается только активное окно.
- Панель персонажа с ником и полосами MP/VP должна быть видна. Перекрытая панель
  намеренно не обрабатывается: при сомнении приложение ничего не нажимает.
- Поддержаны `0%` и `100%`. Неизвестный или противоречивый результат OCR не
  приводит к нажатию.
- Захват выполняется с видимой поверхности экрана. Оконный и безрамочный режимы
  поддерживаются архитектурой напрямую. Эксклюзивный fullscreen зависит от того,
  отдаёт ли конкретная версия клиента кадр Windows GDI, поэтому его необходимо
  проверить на целевом клиенте.
- Приложение не пишет журналы на диск. Диагностический журнал существует только
  в оперативной памяти во время явно открытого диагностического окна. Приложение
  остаётся обычным Windows-процессом и не обещает отсутствие стандартных
  системных артефактов запуска.
