# res-bot

<p align="center">
  <img src="assets/res-bot-icon.png" width="128" height="128" alt="Логотип res-bot">
</p>

`res-bot` — фоновый Windows-помощник для диалога воскрешения в Lineage II. Он
анализирует только изображение активного окна игры и управляет обычным курсором
мыши. Приложение не читает память Lineage II, не внедряет код в процесс, не
устанавливает драйверы и не использует игровые сетевые протоколы.

## Что делает MVP

Раз в 10 секунд приложение:

1. Проверяет, что активное окно похоже на Lineage II.
2. Снимает клиентскую область окна через Windows GDI.
3. Находит диалог воскрешения по паре зелёной и красной кнопок.
4. Распознаёт процент восстановления опыта встроенным Windows OCR.
5. Находит панель персонажа по расположенным рядом цветным полосам MP/VP и
   распознаёт ник в верхней части панели.
6. Выбирает действие по таблице:

| Процент | Ник заканчивается на `_NN` | Действие |
|---:|:---:|:---|
| `0%` | нет | красная кнопка «Отменить» |
| `100%` | нет | зелёная кнопка «ОК» |
| `0%` или `100%` | да | зелёная кнопка «ОК» |

`NN` — ровно две любые цифры от `00` до `99`. Основная часть ника может быть
любой и не задаётся в конфигурации.

Перед нажатием приложение повторно проверяет активное окно и положение диалога.
Курсор движется по плавной кривой со случайной длительностью, а точка нажатия
выбирается внутри безопасной области кнопки.

## Быстрый запуск

Требования:

- Windows 10 или Windows 11 x64;
- установленный русский языковой компонент OCR Windows;
- Lineage II запущена с тем же или более низким уровнем прав, что и `res-bot`.

Запуск:

1. Скачайте `res-bot.exe`.
2. Запустите файл.
3. Убедитесь, что в области уведомлений появился зелёно-золотой значок `res-bot`.
4. Оставьте окно Lineage II активным.

Окно консоли в release-сборке не открывается. Для завершения нажмите левой или правой
кнопкой мыши на значок `res-bot` в системном трее и выберите «Выход». Горячая клавиша
`Ctrl+Shift+F12` остаётся резервным способом завершения.

Без конфигурационного файла используются значения, подходящие для показанных
примеров: интервал 10 секунд и поиск слова `lineage` в заголовке активного окна.

## Необязательная конфигурация

Чтобы изменить параметры, положите рядом с `res-bot.exe` файл `res-bot.toml`.
Все поля обязательны:

```toml
window_title_fragments = ["lineage"]
poll_interval_seconds = 10
click_min_duration_ms = 280
click_max_duration_ms = 650
pre_click_min_delay_ms = 180
pre_click_max_delay_ms = 480
```

Пример также находится в
[`res-bot.example.toml`](res-bot.example.toml).

## Сборка

```powershell
cargo test
cargo build --release
```

Готовый файл появится в `target\release\res-bot.exe`. Все необходимые библиотеки
Rust компонуются в исполняемый файл; отдельный Tesseract и файлы моделей не
нужны. OCR предоставляется самой Windows.

Workflow GitHub Actions собирает и сохраняет `res-bot.exe` как artifact при каждом push
и ручном запуске. При публикации тега вида `v*` тот же workflow создаёт GitHub Release и
прикрепляет к нему готовый `res-bot.exe`.

## Ограничения MVP

- Обрабатывается только активное окно.
- Панель персонажа с ником и полосами MP/VP должна быть видна. Перекрытая панель
  намеренно не обрабатывается: при сомнении приложение ничего не нажимает.
- Поддержаны `0%` и `100%`. Неизвестный или противоречивый результат OCR не
  приводит к нажатию.
- Захват выполняется с видимой поверхности экрана. Оконный и безрамочный режимы
  поддерживаются архитектурой напрямую. Эксклюзивный fullscreen зависит от того,
  отдаёт ли конкретная версия клиента кадр Windows GDI, поэтому его необходимо
  проверить на целевом клиенте.
- Приложение не пишет журналы на диск. Оно остаётся обычным Windows-процессом и
  не обещает отсутствие стандартных системных артефактов запуска.
