# FarNav

<p align="center">
  <img src="assets/res-bot-icon.png" width="128" height="128" alt="Логотип FarNav">
</p>

`FarNav` — фоновый Windows-помощник для диалога воскрешения в Lineage II. Он
может анализировать либо активное окно игры на том же компьютере, либо активное
окно клиента Parsec с видимой трансляцией игры, и управляет обычным курсором
мыши. Приложение не читает память Lineage II, не внедряет код в процесс, не
устанавливает драйверы и не использует игровые сетевые протоколы.

## Что делает MVP

Раз в 10 секунд приложение:

1. Проверяет, что активное окно соответствует выбранному источнику изображения:
   Lineage II или Parsec.
2. Снимает клиентскую область окна через Windows GDI.
3. Находит диалог воскрешения по паре зелёной и красной кнопок.
4. Распознаёт процент восстановления опыта встроенным Windows OCR.
5. Находит панель самого персонажа по набору полос CP/HP/MP/VP, игнорируя
   похожие панели участников группы, и распознаёт ник в верхней части панели.
6. Выбирает действие по таблице:

| Процент | Ник заканчивается на `_NN` | Действие |
|---:|:---:|:---|
| `0%` | нет | красная кнопка «Отменить» |
| `100%` | нет | зелёная кнопка «ОК» |
| `0%` или `100%` | да | зелёная кнопка «ОК» |

`NN` — ровно две любые цифры от `00` до `99`. Основная часть ника может быть
любой и не задаётся в конфигурации.

Перед нажатием приложение подтверждает одинаковые процент, суффикс ника и решение
на нескольких последовательных кадрах, а после ожидания свободной мыши ещё раз
проверяет активное окно и положение диалога. Курсор движется по плавной кривой со
случайной длительностью, а точка нажатия выбирается внутри безопасной области
кнопки.

## Дополнительные функции

- количество подтверждающих кадров и интервал между ними настраиваются;
- учитывается только ручное движение курсора: нажатия кнопок мыши и макросных
  клавиш не блокируют работу;
- если пользователь начинает двигать мышь во время автоматического движения,
  клик отменяется;
- после успешного клика курсор может переместиться в случайную близкую точку;
  функцию можно отключить;
- настройки открываются из трея и применяются без перезапуска;
- самопроверка из трея проверяет OCR, конфигурацию, активное окно, захват кадра,
  диалог и панель персонажа, но никогда не выполняет клик.

## Быстрый запуск

Требования:

- Windows 10 или Windows 11 x64;
- установленный русский языковой компонент OCR Windows;
- возможность подтвердить стандартный запрос контроля учётных записей Windows
  при запуске.

Запуск:

1. Скачайте `FarNav.ScreenAssistant.exe`.
2. Запустите файл и подтвердите запрос Windows на запуск от администратора.
3. Убедитесь, что в области уведомлений появился зелёно-золотой значок `FarNav`.
4. В меню значка выберите «Источник изображения»: «Lineage II» для локальной
   игры или «Parsec» для анализа удалённой трансляции.
5. Оставьте выбранное окно активным.

Порядок запуска не важен: `FarNav` можно открыть до или после игры либо
подключения Parsec. Пока выбранное целевое окно неактивно, приложение остаётся в
ожидании. После переключения на него проверка произойдёт в течение ближайшего
интервала, по умолчанию — не позднее чем через 10 секунд. Приложение всегда
запрашивает права администратора, потому что Lineage II может запускаться с
повышенными правами и Windows иначе блокирует отправку мышиного ввода.

Приложение проверяет доступность русского OCR до появления значка в трее. Если
значок появился без сообщения об ошибке, компонент доступен. Для ручной проверки
откройте Windows PowerShell от имени администратора:

```powershell
Get-WindowsCapability -Online |
  Where-Object { $_.Name -like 'Language.OCR*ru-RU*' }
```

Установленному компоненту соответствует `State : Installed`. Если показано
`NotPresent`, установите его:

```powershell
Get-WindowsCapability -Online |
  Where-Object { $_.Name -like 'Language.OCR*ru-RU*' } |
  Add-WindowsCapability -Online
```

Окно консоли в release-сборке не открывается. В меню значка `FarNav` доступны
«Источник изображения», «Настройки», «Диагностика», «Самопроверка» и «Выход».
Горячая клавиша `Ctrl+Shift+F12` остаётся резервным способом завершения.

Без конфигурационного файла используются значения, подходящие для показанных
примеров: интервал 10 секунд и локальный режим Lineage II. Выбор источника через
трей применяется сразу и сохраняется в `FarNav.ScreenAssistant.toml`.

## Работа через Parsec

В режиме Parsec `FarNav` запускается на клиентском компьютере и анализирует
пиксели активного окна Parsec. Координаты найденной кнопки уже относятся к
клиентской области этого окна, поэтому отдельный пересчёт под разрешение
удалённого компьютера не нужен: локальный клик получает Parsec, который сам
переводит его в координаты экрана хоста.

Для работы режима:

1. Подключитесь к компьютеру с Lineage II и убедитесь, что игра видна в Parsec.
2. В трее `FarNav` выберите «Источник изображения → Parsec».
3. Оставьте окно Parsec активным.
4. Не отсоединяйте ввод Parsec сочетанием `Ctrl+Alt+Z`.
5. Отключите Mouse Immersive Mode, если он удерживает или центрирует локальный
   курсор. Обычный полноэкранный или оконный режим без блокировки мыши
   поддерживается.
6. На хосте разрешите подключённому пользователю управление мышью. Если Lineage
   II работает с повышенными правами, служба Parsec также должна иметь системные
   разрешения.

Изображение приходит после видеокодирования, поэтому слишком низкое разрешение,
битрейт или сильное размытие могут ухудшить OCR и распознавание цветов. При
сомнении приложение ничего не нажимает. Если заголовок подключённого окна не
содержит `parsec`, укажите фактический фрагмент заголовка в настройках.

## Необязательная конфигурация

Чтобы изменить параметры, положите рядом с `FarNav.ScreenAssistant.exe` файл
`FarNav.ScreenAssistant.toml`.
Все поля обязательны:

```toml
window_title_fragments = ["lineage"]
poll_interval_seconds = 10
click_min_duration_ms = 280
click_max_duration_ms = 650
pre_click_min_delay_ms = 180
pre_click_max_delay_ms = 480
confirmation_frame_count = 2
confirmation_interval_ms = 150
mouse_idle_required_ms = 600
mouse_idle_timeout_ms = 3000
relocate_cursor_after_click = true
```

Для режима Parsec установите `window_title_fragments = ["parsec"]`; выбор
источника через трей делает это автоматически.

Пример также находится в
[`farnav.example.toml`](farnav.example.toml).

## Настройки через трей

Окно «Настройки» позволяет менять те же параметры без ручного редактирования
TOML:

- «Применить» обновляет конфигурацию работающего процесса и не создаёт файлов;
- «Сохранить» обновляет процесс и записывает единственный
  `FarNav.ScreenAssistant.toml` рядом с
  `.exe`, чтобы использовать значения после перезапуска;
- «Отмена» закрывает окно без изменений.

Реестр Windows для хранения настроек не используется. Если рядом с `.exe` нельзя
создавать файлы, «Сохранить» покажет конкретную ошибку; «Применить» продолжит
работать без записи.

### Описание параметров

| Поле в окне | Поле TOML | По умолчанию | Допустимые значения | Назначение |
|---|---|---:|---|---|
| Фрагменты заголовка окна | `window_title_fragments` | `lineage` | один или несколько непустых фрагментов | Заголовок активного целевого окна должен содержать хотя бы один фрагмент без учёта регистра. Выбор источника в трее устанавливает `lineage` или `parsec`; в окне настроек значения разделяются запятыми. |
| Интервал проверки, с | `poll_interval_seconds` | `10` | целое число больше `0` | Пауза между циклами поиска диалога. Меньшее значение ускоряет реакцию, но чаще выполняет захват и анализ кадра. |
| Минимальное движение, мс | `click_min_duration_ms` | `280` | целое число больше `0`, не больше максимума | Нижняя граница случайной длительности движения курсора к кнопке. |
| Максимальное движение, мс | `click_max_duration_ms` | `650` | целое число не меньше минимума | Верхняя граница длительности движения курсора к кнопке. |
| Минимальная задержка, мс | `pre_click_min_delay_ms` | `180` | целое число больше `0`, не больше максимума | Минимальная случайная пауза между первым распознаванием и подтверждающими кадрами. |
| Максимальная задержка, мс | `pre_click_max_delay_ms` | `480` | целое число не меньше минимума | Максимальная пауза перед подтверждением решения. |
| Количество кадров | `confirmation_frame_count` | `2` | от `2` до `5` | Сколько последовательных кадров должны дать одинаковые процент, `_NN` и действие. |
| Интервал между кадрами, мс | `confirmation_interval_ms` | `150` | от `50` до `1000` | Пауза между подтверждающими кадрами. |
| Необходимый простой мыши, мс | `mouse_idle_required_ms` | `600` | от `100` до `3000` | Сколько времени курсор пользователя должен оставаться неподвижным до начала автоматического движения. Нажатия кнопок мыши не считаются движением. |
| Максимальное ожидание мыши, мс | `mouse_idle_timeout_ms` | `3000` | от значения простоя до `10000` | Сколько максимум ждать свободного курсора. После тайм-аута текущий клик отменяется. |
| Случайно перемещать курсор после клика | `relocate_cursor_after_click` | включено | включено или выключено | После подтверждённого клика перемещает курсор в случайную близкую точку. При выключении курсор остаётся на кнопке. |

Некорректные значения не применяются: окно показывает ошибку с названием поля.
Изменение настроек запускает ближайший цикл проверки заново. Для типового
использования рекомендуется оставить значения по умолчанию и менять только
интервал проверки либо функцию перемещения курсора после клика.

## Как работает распознавание

Полный кадр не передаётся OCR целиком. Сначала приложение ищет цветовые и
геометрические признаки интерфейса:

1. Пара похожих кнопок «зелёная слева, красная справа» определяет кандидат
   диалога.
2. Область над кнопками обрезается, переводится в контрастный вид, увеличивается
   и передаётся русскому Windows OCR. Если основной проход пропустил процент,
   отдельно распознаётся увеличенный участок со строкой процентов.
3. В совокупном OCR-тексте ищется отдельное `0%` либо `100%`; противоречивый
   результат считается небезопасным и отклоняется.
4. Панель самого персонажа независимо ищется по структуре полос CP/HP/MP/VP в
   любой части кадра. Панели группы без длинной полосы VP не считаются панелью
   персонажа.
5. Заголовок панели распознаётся отдельно с большим увеличением. Проверяется
   суффикс `_NN`, включая безопасную обработку случая, когда OCR потерял
   подчёркивание, но сохранил две финальные цифры.
6. Процент, наличие `_NN` и итоговое действие должны совпасть на 2–5
   последовательных кадрах.
7. После ожидания неподвижного курсора повторно проверяются активное окно, HWND
   и положение диалога. После ввода проверяется исчезновение диалога; только
   после этого диагностика сообщает «Клик подтверждён».

Если процент, панель или похожий на ник текст не распознаны однозначно,
приложение ничего не нажимает и продолжает работу.

## Диагностика по запросу

Диагностика по умолчанию выключена и не создаёт файлов.

1. Нажмите левой или правой кнопкой мыши на значок `FarNav` в трее.
2. Выберите «Диагностика».
3. Вернитесь в выбранное окно Lineage II или Parsec и воспроизведите сценарий.
4. Просмотрите журнал в диагностическом окне. Оно остаётся поверх других окон,
   но не должно активироваться вместо игры.
5. Используйте «Копировать», чтобы поместить весь журнал в буфер обмена, либо
   «Очистить», чтобы начать новую диагностическую последовательность.
6. Закройте диагностическое окно, чтобы остановить сбор.

Во время диагностической сессии в оперативной памяти хранится не более 500
строк. Записываются результаты проверки окна, размеры кадра, координаты
найденного диалога и панелей, OCR-текст, решение, повторная проверка и итоговый
клик. После закрытия окна новые строки не формируются; на диск журнал
автоматически не сохраняется.

## Самопроверка

1. Откройте меню значка в трее и выберите «Самопроверка».
2. Подтвердите запуск и в течение трёх секунд вернитесь в выбранное целевое
   окно.
3. Дождитесь окна с результатами.

Самопроверка отмечает каждый этап как `[OK]`, предупреждение `[!]` или ошибку
`[X]`. Отсутствие открытого диалога воскрешения является предупреждением, а не
ошибкой захвата. Во время самопроверки автоматические клики приостановлены.

## Если бот не нажимает кнопку

Откройте диагностику, вернитесь в игру и дождитесь следующего цикла. Наиболее
частые причины:

- выбранное окно Lineage II или Parsec не является активным;
- заголовок окна не содержит настроенный фрагмент `lineage` или `parsec`;
- в режиме Parsec ввод отсоединён либо Mouse Immersive Mode удерживает курсор;
- качество трансляции Parsec недостаточно для уверенного распознавания;
- не найдена подходящая пара зелёной и красной кнопок;
- русский OCR не обнаружил `0%` или `100%`;
- не найдена видимая панель самого персонажа с полосами CP/HP/MP/VP;
- OCR не распознал похожий на ник текст;
- окно или диалог изменились во время задержки перед кликом;
- запрос UAC при запуске не был подтверждён.

## Сборка

```powershell
cargo test
cargo build --release
```

Cargo создаёт `target\release\farnav-screen-assistant.exe`; workflow переименовывает
его в итоговый `FarNav.ScreenAssistant.exe`. Все необходимые библиотеки
Rust компонуются в исполняемый файл; отдельный Tesseract и файлы моделей не
нужны. OCR предоставляется самой Windows.

Workflow GitHub Actions собирает и сохраняет `FarNav.ScreenAssistant.exe` вместе с
`SHA256SUMS.txt` как artifact при каждом push и ручном запуске. При публикации
тега вида `v*` тот же workflow создаёт GitHub Release и прикрепляет к нему оба
файла.

## Ограничения MVP

- Обрабатывается только активное окно.
- Панель самого персонажа с ником и полосами CP/HP/MP/VP должна быть видна.
  Панели группы игнорируются. Перекрытая панель персонажа намеренно не
  обрабатывается: при сомнении приложение ничего не нажимает.
- Поддержаны `0%` и `100%`. Неизвестный или противоречивый результат OCR не
  приводит к нажатию.
- Захват выполняется с видимой поверхности экрана. Оконный и безрамочный режимы
  поддерживаются архитектурой напрямую. Эксклюзивный fullscreen зависит от того,
  отдаёт ли конкретная версия клиента кадр Windows GDI, поэтому его необходимо
  проверить на целевом клиенте.
- Приложение не пишет журналы на диск. Диагностический журнал существует только
  в оперативной памяти во время явно открытого диагностического окна. Приложение
  остаётся обычным Windows-процессом и не обещает отсутствие стандартных
  системных артефактов запуска.
