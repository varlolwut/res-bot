# Техническое решение res-bot

## 1. Цель и границы

MVP автоматизирует единственный сценарий: обработку диалога воскрешения в
активном окне Lineage II на Windows. Источник данных — только пиксели видимой
клиентской области. Выходное воздействие — обычное перемещение курсора и нажатие
левой кнопки.

За границами MVP:

- чтение памяти и внутренних структур игры;
- инъекции DLL, хуки и драйверы;
- сетевой анализ игрового протокола;
- работа со свёрнутым окном;
- несколько окон одновременно;
- обработка перекрытой панели персонажа.

## 2. Компоненты

```text
Foreground window
       │
       ▼
Win32 window validation ── title fragments + client coordinates
       │
       ▼
GDI screen capture ─────── BGRA frame in memory
       │
       ├──► colored-component detector ──► resurrection dialog + buttons
       │                                     │
       │                                     ▼
       │                                  Windows OCR ──► 0% / 100%
       │
       └──► status-bar detector ─────────► player panel
                                             │
                                             ▼
                                          Windows OCR ──► suffix _NN
                                                              │
                                                              ▼
                                                     pure decision function
                                                              │
                                                              ▼
                                         revalidate window and dialog position
                                                              │
                                                              ▼
                                                curved cursor motion + SendInput
```

Модули:

- `config.rs` — встроенная и необязательная TOML-конфигурация;
- `image.rs` — типы кадра и геометрии, crop, масштабирование и подготовка OCR;
- `detection.rs` — поиск цветовых компонент, кнопок и панели персонажа;
- `decision.rs` — разбор процента, суффикса и таблица решения;
- `platform/window.rs` — активное окно, DPI и экранные координаты;
- `platform/capture.rs` — захват BGRA через GDI;
- `platform/ocr.rs` — адаптер Windows Runtime OCR;
- `platform/input.rs` — движение курсора и `SendInput`;
- `platform/tray.rs` — скрытое окно Win32, значок области уведомлений и команда «Выход»;
- `platform/notify.rs` — фатальные сообщения и диагностический OutputDebugString.

## 3. Захват изображения

После включения Per-Monitor DPI Awareness V2 приложение получает активное окно,
его client rectangle и преобразует начало клиентской области в экранные
координаты.

Захват выполняется через:

1. `GetDC(NULL)` для видимой поверхности экрана;
2. совместимый memory DC;
3. top-down 32-bit DIB section;
4. `BitBlt` в DIB;
5. копирование BGRA в типизированный `Frame`.

Объекты GDI обёрнуты в RAII-адаптеры и освобождаются через `ReleaseDC`,
`DeleteDC` и `DeleteObject`, включая ошибочные ветки. Захват повторяется до трёх
раз при ошибке, после чего ошибка показывается пользователю.

## 4. Поиск диалога

Полный OCR кадра не используется: он медленнее и даёт больше ложных совпадений.
Сначала пиксели классифицируются по цвету.

Для зелёных и красных пикселей строятся связные компоненты. Компоненты
фильтруются по:

- диапазону ширины и высоты;
- заполненности bounding box;
- взаимному размеру;
- близкой координате Y;
- порядку «зелёная слева, красная справа»;
- допустимому зазору между кнопками.

Границы диалога вычисляются относительно размеров найденных кнопок, поэтому
алгоритм не привязан к абсолютному разрешению экрана. Если найдено несколько
пар, приоритет получает наиболее крупная и близкая к центру.

Перед кликом делается второй кадр. Центр и размеры диалога должны остаться в
заданном допуске.

## 5. OCR процента

Диалог обрезается, преобразуется в контрастное чёрно-белое изображение и
увеличивается в три раза nearest-neighbor масштабированием. Это помогает
встроенному `Windows.Media.Ocr` с мелким игровым шрифтом.

Парсер ищет:

- точную последовательность `100%`;
- отдельную последовательность `0%`, перед которой нет цифры.

Последнее условие не позволяет ошибочно принять хвост `100%` за `0%`. Скобки
намеренно не обязательны: на предоставленных изображениях Windows OCR иногда
распознаёт закрывающую `)` как `}`.

Если обе величины обнаружены одновременно или не найдена ни одна, клик не
выполняется.

## 6. Поиск панели и суффикса ника

Положение панели не фиксировано. Детектор ищет близкие горизонтальные синие и
зелёные компоненты, соответствующие полосам MP и VP:

- небольшая высота;
- достаточная ширина и заполненность;
- похожее начало и ширина;
- зелёная полоса находится немного ниже синей.

Из найденной геометрии строится регион, включающий верхнюю строку с уровнем и
ником. Для панели лучше работает исходное цветное изображение, увеличенное в три
раз, поэтому здесь не применяется бинаризация.

После удаления пробелов OCR-текст проверяется на `_NN`, где обе позиции `N` —
ASCII-цифры, а третья цифра после них отсутствует. Основная часть ника не
настраивается и может быть любой.

Если панель или похожий на имя текст не распознаны, действие отменяется. Это
fail-closed поведение исключает ошибочный отказ от `0%`, когда у персонажа мог
быть цифровой суффикс.

## 7. Решение и ввод

Решение реализовано чистой функцией:

```text
numbered suffix OR percentage == 100  => Accept
otherwise percentage == 0             => Reject
```

Перед вводом проверяется, что:

- окно Lineage II всё ещё активно;
- HWND совпадает с первоначальным;
- диалог всё ещё найден;
- его положение и размер почти не изменились.

Точка клика выбирается случайно внутри кнопки с отступом от краёв. Траектория —
кубическая кривая Безье с небольшим случайным изгибом и длительностью из
конфигурации. Позиция меняется через `SetCursorPos`, нажатие отправляется парой
`MOUSEEVENTF_LEFTDOWN`/`MOUSEEVENTF_LEFTUP` через `SendInput`.

## 8. Ошибки и наблюдаемость

Фатальные ошибки имеют конкретный тип и контекст операции. В release-сборке
ошибка показывается через `MessageBoxW`. Повторные ошибки захвата/OCR доступны
отладчику через `OutputDebugStringW`; файловые журналы не создаются.

Отсутствие диалога, неактивное окно и неопределённое распознавание являются
нормальными состояниями цикла и не считаются ошибками.

## 9. Проверки

Автоматические тесты покрывают:

- геометрию кадра и crop;
- поиск синтетической пары кнопок;
- поиск синтетических полос панели;
- разбор `0%` и `100%`;
- строгий двухцифровой суффикс;
- таблицу решения;
- крайние точки кривой Безье;
- валидацию конфигурации.

Дополнительные ignored-тесты принимают внешний BGRA-кадр через переменные
окружения. Ими проверены предоставленные скриншоты:

- точное нахождение кнопок на обоих полноэкранных кадрах;
- OCR `0%` и `100%`;
- OCR ника `lonedy` на неперекрытой панели;
- OCR и правило `_NN` на синтетической панели с другим ником.

## 10. Развитие до нескольких окон

Следующий этап не должен зависеть от активного окна:

1. перечислять подходящие HWND;
2. завести независимое состояние на окно;
3. перейти на Windows Graphics Capture или DXGI Desktop Duplication;
4. хранить отдельный cooldown и последний dialog fingerprint для каждого HWND;
5. отправлять ввод только после безопасной активации нужного окна либо через
   разрешённый сервером механизм фонового ввода.

Решение, детекторы и OCR-регионы уже не зависят от глобального состояния, поэтому
для многоконного режима потребуется заменить главным образом планировщик,
источник кадров и маршрутизацию ввода.
